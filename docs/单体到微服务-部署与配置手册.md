# 单体 → 微服务：部署改动与配置详解

> 适用：腾讯云轻量 2核4G + 宝塔，域名 `www.nestparts.top`  
> 版本：v3.2.0（`ms/dev`）  
> 目的：复盘「家里能像以前一样用域名」，同时方便面试讲清部署链路

---

## 0. 一句话总览

| 以前（单体） | 现在（微服务） |
|--------------|----------------|
| 1 个 Spring Boot（常见 8080） | Nacos + 5 个 jar（platform/inventory/order/ai/gateway） |
| Nginx：`root` 旧前端，`/api` → `8080` | Nginx：`root` 新前端，`/api` → Gateway `9080` |
| 配置多在 jar 内或单体 yml | 公共 yml + `dev`/`prd` + 服务器 `env.sh` 注入密钥 |

浏览器仍只打开 **https://www.nestparts.top**，妈妈用法不变。

```text
浏览器
  → Nginx:443（www.nestparts.top）
      ├─ 静态页  → /www/wwwroot/inventory-ms-front
      ├─ /api/*  → 127.0.0.1:9080  Gateway
      │              ├─ /api/platform|goods|auth... → platform-service:8081
      │              ├─ /api/inventory/**           → inventory-service:8082
      │              ├─ /api/order/**               → order-service:8083
      │              └─ /api/ai/**                  → ai-service:8084
      └─ /upload/* → 磁盘 /opt/upload/（与单体相同）
```

## 1. 部署时实际改过哪些操作

按时间线记「你在服务器 / 本机做过什么」，不是代码清单。

### 1.1 准备阶段（同机共存）

1. **目录**  
   - 后端：`/www/wwwroot/inventory-ms-backend/`（`jars/`、`nacos/`、`logs/`、`scripts/`）  
   - 前端：`/www/wwwroot/inventory-ms-front/`  
   - 密钥：`/opt/inventory-ms/env.sh`（`chmod 600`，**不进 Git**）
2. **装 / 确认 JDK 17**，与本地一致。  
3. **解压 Nacos**，单机模式启动，端口 **8848**。  
4. **安全组 / 宝塔防火墙**：练习期放过 **9080**（Gateway）；8848 仅调试时对公网开。  
5. **数据库 / Redis**：继续用本机已有 PostgreSQL、Redis（与练习库共用；门店那两张表无关）。

### 1.2 后端微服务上线

1. 本机 Maven 打包各服务 jar（跳过测试：`-DskipTests`）。  
2. 上传 `*-3.x.x.jar` 到 `jars/`。  
3. 写好 `/opt/inventory-ms/env.sh`（见第 2 节）。  
4. 若从 Windows 上传脚本：`sed -i 's/\r$//' 文件` 去掉 `\r`。  
5. 先起 Nacos，再 `start-all.sh`（或按 platform → inventory → order → ai → gateway 顺序起）。  
6. 验收：`curl` Gateway ping；Nacos 控制台看服务是否健康。  
7. **停掉单体 jar**（否则域名仍指单体时会混；切域名后单体可不必再起）。

### 1.3 前端与域名切流（妈妈能照常用）

1. 本机 `store-inventory-front-ms`：`npm run build`。  
2. 上传 `dist/` 内容到 `/www/wwwroot/inventory-ms-front/`（必须含同级 `index.html` + `assets/`）。  
3. 改 Nginx（宝塔站点配置）：  
   - `root`：旧 `inventory-front` → `inventory-ms-front`  
   - `/api`：`8080` → `127.0.0.1:9080`  
   - `/upload`：继续 `alias /opt/upload/;`（推荐）  
   - 保留 80/443 跳转到 `https://www.nestparts.top`  
4. 重载 Nginx。  
5. 浏览器登录验收；AI 若 503 → 多半是 `ai-service` 没起来或缺 `DASHSCOPE_API_KEY`。

### 1.4 和「没改」的东西

| 项 | 说明 |
|----|------|
| 域名 / SSL 证书 | 仍用宝塔那套 `nestparts.top` 证书 |
| PostgreSQL / Redis 实例 | 同机复用，密码走环境变量 |
| 上传目录 `/opt/upload` | 路径习惯与单体 prd 一致 |
| 旧前端目录 | 可留作回滚备份，不必删 |

完整 Nginx 备份与微服务版见：`docs/nginx/`。

## 2. 启动与配置文件详解

配置分三层，记这个就够用：

```text
① 仓库里的 application*.yml     → 写「怎么连库、端口、路由」
② 服务器 /opt/inventory-ms/env.sh → 写「密钥、profile=prd」
③ Nginx 站点配置                 → 写「域名如何转到前端/Gateway」
```

启动脚本只是把 ② 读进来，再 `java -jar`。

---

### 2.1 `/opt/inventory-ms/env.sh`（服务器密钥，最重要）

仓库模板：`scripts/env.sh.example`  
线上真实文件：**只在服务器**，权限 `600`。

| 变量 | 作用 |
|------|------|
| `JAVA_HOME` / `PATH` | 找到 JDK 17；PATH 必须含 `/usr/bin`，否则 `mkdir`/`ss` 会 “command not found” |
| `SPRING_PROFILES_ACTIVE=prd` | 激活各服务的 `application-prd.yml` |
| `DB_PWD` | 数据库密码 → 映射到 `spring.datasource.password` |
| `REDIS_HOST` / `REDIS_PWD` | Redis 地址与密码 |
| `DASHSCOPE_API_KEY` | 通义 Key → `spring.ai.openai.api-key`；**缺则 ai-service 启动失败，Gateway 对 /api/ai 报 503** |

加载方式：

```bash
. /opt/inventory-ms/env.sh          # 注意前面有个点（source）
# 或
source /opt/inventory-ms/env.sh
```

`start-all.sh` 内部会自动 `. "$ENV_FILE"`，一般不必手敲。

**Windows 上传后必做：**

```bash
sed -i 's/\r$//' /opt/inventory-ms/env.sh
```

否则会出现：`-bash: $'\r': command not found`。

---

### 2.2 Spring：`application.yml` + `dev` / `prd`

每个服务目录大致是：

```text
xxx-service/src/main/resources/
  application.yml        # 公共：端口、服务名、Nacos、公共默认值
  application-dev.yml    # 本地：本机路径、调试日志、本地 CORS
  application-prd.yml    # 生产：/opt/upload、域名 CORS、生产日志级别
```

关键开关（公共 yml 里）：

```yaml
spring:
  profiles:
    active: ${SPRING_PROFILES_ACTIVE:dev}   # 没设环境变量时默认 dev
```

含义：

- 本机 IDEA 不设变量 → **dev**  
- 服务器 `env.sh` 写了 `prd` → **prd**  
- Spring 会把「公共 + 对应 profile」合并；同名项以 profile 为准  

**举例 platform：**

| 配置项 | 公共 / 环境变量 | prd 里常写 |
|--------|-----------------|------------|
| 端口 8081、服务名、Nacos | `application.yml` | — |
| 上传路径 | — | `/opt/upload/...`，图片 URL 前缀用域名 |
| CORS | — | `https://www.nestparts.top` 等 |
| DB/Redis 密码 | `${DB_PWD}` / `${REDIS_PWD}` | 一般只强调从环境变量读 |

Gateway 公共 yml 里还有 **路由表**（`Path=/api/order/**` → `lb://order-service` 等）。  
`lb://` 表示从 Nacos 按服务名负载均衡，所以 **业务服务必须先注册成功**，Gateway 才能转发。

---

### 2.3 `scripts/start-all.sh` / `stop-all.sh`

| 脚本 | 做什么 |
|------|--------|
| `start-all.sh` | 读 `env.sh` → 检查 8848 → 按顺序 `nohup java -jar` → 打日志到 `logs/` |
| `stop-all.sh` | 按 jar 名 `pkill` 各业务进程（**不停 Nacos**） |

默认路径：

```text
MS_HOME=/www/wwwroot/inventory-ms-backend
JARS=$MS_HOME/jars/*-3.2.0.jar
LOGS=$MS_HOME/logs
ENV_FILE=/opt/inventory-ms/env.sh
```

启动顺序（脚本内）：platform → inventory → order → ai → gateway。  
JVM：`-Xms128m -Xmx256m`（2核4G 省内存）。

**注意：** jar 文件名版本要和脚本一致（当前脚本认 `*-3.2.0.jar`）。线上若仍是 `3.1.0` jar，要么改脚本版本号，要么重新打包上传 3.2.0。

单独起 AI（配好 Key 后）：

```bash
. /opt/inventory-ms/env.sh
cd /www/wwwroot/inventory-ms-backend
nohup java -Xms128m -Xmx256m -jar jars/ai-service-3.1.0.jar >> logs/ai-service.log 2>&1 &
# 若已换成 3.2.0 jar，把文件名改成 3.2.0
```

---

### 2.4 Nacos

- 目录示例：`/www/wwwroot/inventory-ms-backend/nacos`  
- 启动：`cd nacos/bin && sh startup.sh -m standalone`  
- 控制台：`http://服务器IP:8848/nacos`（公网开放时注意安全，用完可关）  
- 作用：服务注册与发现；Gateway 用服务名找实例  

没有 Nacos → 业务 jar 可能起得来，但 Gateway `lb://` 会失败（常见 503）。

---

### 2.5 Nginx（域名入口）

存档：

- `docs/nginx/nginx-nestparts-monolith.conf` — 单体备份 + 注释  
- `docs/nginx/nginx-nestparts-ms.conf` — 微服务版  

微服务关键两处：

```nginx
root /www/wwwroot/inventory-ms-front;

location /api/ {
    proxy_pass http://127.0.0.1:9080;
    # ... 常见 proxy_set_header
}

location ^~ /upload/ {
    alias /opt/upload/;
}
```

前端生产环境：`VITE_API_BASE_URL=/api`（同源），所以浏览器不会直连 9080。

---

### 2.6 前端构建产物

```text
本机：store-inventory-front-ms → npm run build → dist/
服务器：/www/wwwroot/inventory-ms-front/
         ├── index.html    ← 必须与 assets 同级
         ├── assets/
         └── brand/
```

只传了 `assets` 没传 `index.html` → 白屏 / 打不开。

## 3. 日常启停与验收（抄命令）

### 3.1 推荐一键

```bash
# 1) Nacos（若未起）
cd /www/wwwroot/inventory-ms-backend/nacos/bin
sh startup.sh -m standalone

# 2) 业务
cd /www/wwwroot/inventory-ms-backend/scripts
sed -i 's/\r$//' start-all.sh stop-all.sh   # 若刚从 Windows 上传
chmod +x start-all.sh stop-all.sh
./start-all.sh

# 3) 停止业务（不停 Nacos）
./stop-all.sh
```

### 3.2 验收

```bash
ss -lntp | grep -E '8848|8081|8082|8083|8084|9080'
curl -s http://127.0.0.1:9080/api/order/ping
curl -s http://127.0.0.1:9080/api/ai/ping
curl -s http://127.0.0.1:9080/api/platform/ping
```

浏览器：`https://www.nestparts.top` → 登录 → Network 里 API 应为 `https://www.nestparts.top/api/...`。

### 3.3 看日志

```bash
cd /www/wwwroot/inventory-ms-backend/logs
tail -n 80 ai-service.log
tail -n 80 gateway-service.log
tail -f platform-service.log    # 持续看，Ctrl+C 退出
```

## 4. Linux 常用命令（部署会用到）

### 4.1 目录与文件

| 命令 | 含义 |
|------|------|
| `pwd` | 当前目录 |
| `ls -lah` | 列文件（含隐藏、权限、大小） |
| `cd /path` | 进入目录 |
| `mkdir -p a/b` | 递归创建目录 |
| `cp -r src dest` | 复制 |
| `mv a b` | 移动/改名 |
| `rm -rf dir` | 删除（慎用） |
| `chmod +x script.sh` | 可执行 |
| `chmod 600 env.sh` | 仅所有者读写（密钥文件） |
| `chown -R www:www dir` | 改属主（宝塔站点常用 www） |
| `du -sh *` | 看各目录占多少盘 |
| `df -h` | 磁盘剩余 |

### 4.2 编辑与换行

| 命令 | 含义 |
|------|------|
| `vi文件` / `nano 文件` | 编辑 |
| `sed -i 's/\r$//' 文件` | 去掉 Windows `\r` |
| `cat 文件` | 打印全文 |
| `head -n 20` / `tail -n 50` | 看头/尾 |
| `grep -n 关键字 文件` | 搜索 |

### 4.3 进程与端口

| 命令 | 含义 |
|------|------|
| `ss -lntp` | 看谁在听哪些端口（推荐） |
| `ss -lntp \| grep 9080` | 只看 Gateway |
| `pgrep -af ai-service` | 按名字找 Java 进程 |
| `pkill -f 'ai-service-3.1.0.jar'` | 按 jar 名停进程 |
| `kill PID` / `kill -9 PID` | 结束进程（-9 强杀） |
| `ps aux \| grep java` | 粗看 Java 进程 |
| `free -h` | 内存 |
| `top` / `htop` | CPU/内存实时 |

### 4.4 后台启动与日志

| 命令 | 含义 |
|------|------|
| `nohup 命令 >>a.log 2>&1 &` | 后台跑，关掉 SSH 也继续；标准错误并进日志 |
| `echo $!` | 刚启动进程的 PID |
| `tail -f xxx.log` | 跟踪日志 |
| `curl -s URL` | 静默请求（探活） |
| `curl -i URL` | 看响应头（状态码） |

### 4.5 环境变量

| 命令 | 含义 |
|------|------|
| `export A=b` | 当前 shell 生效 |
| `. /opt/inventory-ms/env.sh` | 加载一整文件变量 |
| `echo $DASHSCOPE_API_KEY` | 查看（**勿截图发给别人**） |
| `[ -n "$DASHSCOPE_API_KEY" ] && echo ok` | 只判断有没有值 |

### 4.6 Nginx / 宝塔相关

| 命令 | 含义 |
|------|------|
| `nginx -t` | 检查配置语法 |
| `nginx -s reload` | 重载（或宝塔点「重载配置」） |
| `tail -n 50 /www/wwwlogs/nginx_error.log` | Nginx 错误日志 |

站点配置常见位置（宝塔）：面板「网站 → 设置 → 配置文件」，或 `/www/server/panel/vhost/nginx/`。

### 4.7 网络排错思路

```bash
# 本机 Gateway 通不通
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:9080/api/order/ping

# 某个服务自己通不通（绕过 Gateway）
curl -s http://127.0.0.1:8084/api/ai/ping

# 端口没起来 → 看对应 log 末尾
tail -n 100 /www/wwwroot/inventory-ms-backend/logs/ai-service.log
```

常见对应：

| 现象 | 优先查 |
|------|--------|
| 域名 502 | Nginx 反代端口 / Gateway 是否在 9080 |
| 登录以外业务 503 | Nacos 里有无该服务；jar 是否挂了 |
| 仅 AI 503 | `ai-service` + `DASHSCOPE_API_KEY` |
| `$'\r': command not found` | `sed -i 's/\r$//' 脚本` |
| `mkdir: command not found` | `env.sh` 的 PATH 缺 `/usr/bin` |

## 5. 回滚（万一要回到单体页面）

1. Nginx：`root` 改回 `/www/wwwroot/inventory-front`（或你的旧目录）。  
2. `/api` 的 `proxy_pass` 改回单体端口（如 `8080`），并启动单体 jar。  
3. `nginx -s reload`。  

微服务目录与 `inventory-ms-front` 可先留着，不影响回滚。

## 7. 面试可怎么说（30 秒）

> 业务拆成多个 Spring Boot，经 Nacos 注册，统一从 Gateway 暴露；生产用 `SPRING_PROFILES_ACTIVE=prd` 和服务器 `env.sh` 注入密钥。域名仍由 Nginx 终结 TLS，静态资源指新前端，`/api` 反代到本机 Gateway 9080，上传目录继续走磁盘。同机 2核4G 上限制各进程堆内存，AI 依赖 DashScope Key，缺 Key 时服务起不来会导致该路由 503。
