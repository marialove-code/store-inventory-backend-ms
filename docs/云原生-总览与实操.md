## 1. 云原生在说什么（一句）

**云原生** ≈ 应用按「可复制的运行单元」交付（常见是**容器**），而不是只靠某台机器手动丢 jar。

你们项目：业务已 Docker 化（本机五服务 + 服务器 order）；中间件（Nacos/PG/Redis/Nginx）刻意留宿主机。

---

## 2. Docker vs K8s（面试够用）

| | Docker | Kubernetes |
|--|--------|------------|
| 是什么 | 容器引擎：镜像 / 容器 | 容器编排：多机多副本 |
| 解决什么 | 环境一致、统一启动 | 扩缩、滚动发布、自愈 |
| 本项目 | **已动手** | **只口述** |

常用词：镜像≈安装包；容器≈运行实例；Dockerfile≈造镜像说明书。  
compose = 本机/单机多容器编排，**不是** K8s。

K8s 口述挂钩项目：多副本 → 要 **V5 分布式锁**；滚动/重试 → 要 **V7 幂等**。

## 4. 实操速查

### 4.1 本机：只起 order（复习）

```powershell
cd E:\Projects\store-inventory-backend-ms
mvn -pl order-service -am -DskipTests package
docker build -f order-service/Dockerfile -t inventory-order:3.6.0 .
# 探活：http://localhost:8083/api/order/ping
```

更完整步骤见原 Day1 专文（已并入本入口，命令同上）。多阶段构建见 `order-service/Dockerfile.multistage`。

### 4.2 本机：五服务

见 **[云原生-五服务容器启动.md](./云原生-五服务容器启动.md)**（`install` → build 五镜像 → `docker-compose.dev.yml`）。

中间件仍：Nacos/PG/Redis 宿主机；ES/RabbitMQ 用 Desktop 已有容器。

### 4.3 服务器：order 一键部署脚本

```bash
bash /www/wwwroot/inventory-ms-backend/scripts/deploy-order-docker.sh
curl -s http://127.0.0.1:8083/api/order/ping
```

依赖：`deploy/order-runtime/Dockerfile` + jar + `/opt/inventory-ms/env.sh`。

### 4.4 CI/CD（中厂实用）

见 **[CI-CD-order中厂自动化部署.md](./CI-CD-order中厂自动化部署.md)**：

- push `ms/dev` → Order-CI 只编译  
- tag `order-v*` / 手动 → Order-CD（部署阶段需确认）→ 调上述脚本
