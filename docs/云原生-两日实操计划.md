# 云原生 · 两日实操计划（基于 store-inventory-backend-ms）

> 目标：把「手动上传 jar」升级为「镜像 / 容器可演示」；K8s 与生产自动发布只口述。  
> 原则：**本机实验**；少写业务代码，以配置 + 调试为主。  
> 前置：本机已有 Docker、JDK17、Nacos、能 `mvn package`。  
> **先读概念：** [`云原生-Docker与K8s入门.md`](./云原生-Docker与K8s入门.md)  
> **Day1 操作：** [`云原生-Day1-order容器化.md`](./云原生-Day1-order容器化.md)  
> 关联：[`学习路线-下一阶段.md`](./学习路线-下一阶段.md) P6 / P7。

## 0. 范围与不做

### 两天要做成

| 产出 | 说明 |
|------|------|
| 至少 2 个业务服务的 `Dockerfile` | 建议 `gateway-service` + `order-service` |
| 根目录 `docker-compose.dev.yml` | 跑通「网关 → 订单」最小链路（或网关探活 + 订单探活） |
| 一份口述稿 | 镜像 / 编排 / 探针 / 内存 / 滚动发布 ↔ V5·V7 |
| （可选）Gitee Actions 构建流水线 | push 后 `mvn -DskipTests package` 绿 |

### 明确不做

- 门店服务器整机改容器 / 自动部署到生产
- 一次 compose 拉齐 PG + Redis + ES + 全部 5 服务（调试成本爆炸）
- 完整 K8s 集群、Service Mesh
- 为容器重写业务代码

### 依赖怎么处理（关键决策）

**中间件继续用你现在本机已起的**（Nacos / PG 隧道 / Redis / RabbitMQ / ES），容器里的业务服务通过 `host.docker.internal`（Windows Docker Desktop）访问宿主机。

这样两天只解决「业务 jar → 镜像 → 容器网络」，不把中间件再容器化一遍。

```text
[容器] gateway:8080  ──┐
[容器] order:8083    ──┼──► host.docker.internal:8848 Nacos
                       ├──► host.docker.internal:5432 PG（若走隧道）
                       └──► host.docker.internal:6379 Redis 等
[宿主机] 你现有的 Nacos / DB / Redis / MQ / ES
```

## 2. Day 1 — 单服务镜像跑通（约 4～6 小时）

### 上午：概念 30 分钟 + 打通 order

1. **口述对齐**
   - 镜像 = 只读模板；容器 = 运行实例
   - Dockerfile 多阶段：`maven:3.9-eclipse-temurin-17` 构建 → `eclipse-temurin:17-jre` 运行
2. **本机先确认 jar 能起**
   ```bash
   mvn -pl order-service -am -DskipTests package
   java -jar order-service/target/order-service-*.jar
   # 探活（按你们实际路径，常见 /api/.../ping）
   ```
3. **为 `order-service` 写 Dockerfile**（仓内路径建议：`order-service/Dockerfile`）
   - 构建上下文：仓库根目录（方便 `-am` 依赖 common）
   - 或：根目录统一 `Dockerfile.order` + compose `build.context: .`
4. **build & run**
   ```bash
   docker build -f order-service/Dockerfile -t inventory-order:3.6.0 .
   docker run --name order-c -p 8083:8083 \
     -e SPRING_PROFILES_ACTIVE=dev \
     -e SPRING_CLOUD_NACOS_DISCOVERY_IP=host.docker.internal \
     # 其它 DB/Redis 主机改指向 host.docker.internal（或 compose 里 environment）
     inventory-order:3.6.0
   ```
5. **验收**
   - [ ] `docker ps` 看到容器 Up
   - [ ] 宿主机能调通订单探活
   - [ ] Nacos 控制台能看到实例（IP 注意是可达地址）

### 下午：gateway 同样走一遍 + 踩坑笔记

1. 复制套路给 `gateway-service`
2. 网关容器访问 `lb://order-service`：依赖 Nacos 里 order 注册地址对网关可达  
   - 常见坑：容器注册了 `172.x` 而网关打不通 → 统一用 `host.docker.internal` 或固定 `network_mode`/compose 网络
3. 写进笔记 5 条「今天踩坑」（端口占用、Nacos IP、时区、内存、profile）

### Day 1 结束标准

- [ ] `order` 容器可探活  
- [ ] `gateway` 容器可探活（或至少镜像 build 成功）  
- [ ] 能用 3 句话说明：为什么要镜像、多阶段构建干啥、和手动上传 jar 差在哪

## 3. Day 2 — compose + 口述挂项目 +（可选）CI（约 4～6 小时）

### 上午：`docker-compose.dev.yml`

最小服务集（推荐）：

```yaml
# 示意：正式文件动手时再写全
services:
  order-service:
    build: ...
    ports: ["8083:8083"]
    extra_hosts: ["host.docker.internal:host-gateway"]
    environment:
      SPRING_PROFILES_ACTIVE: dev
      # Nacos / Redis / DB 指向宿主机
  gateway-service:
    build: ...
    ports: ["8080:8080"]
    depends_on: [order-service]
```

验收：

- [ ] `docker compose -f docker-compose.dev.yml up --build -d`
- [ ] 浏览器 / curl：`http://localhost:8080/...` 经网关打到订单（或至少两服务 ping 通）
- [ ] `docker compose down` 可干净停掉

**仍放宿主机的：** Nacos、PostgreSQL、Redis、RabbitMQ、ES（你已有的）。  
**进 compose 的：** 先 gateway + order；有余力再加 `inventory-service`。

### 下午前半：云原生口述（挂回本项目）

准备一张表，面试直接背：

| 云原生点 | 挂本项目 |
|----------|----------|
| 镜像 | `inventory-order:3.6.0` 可复现运行 |
| 编排 | compose = 本机；生产可换成 K8s |
| 探针 | Spring Actuator `/actuator/health`（若未开，口述「应加 readiness」） |
| 内存 | 容器 limit > 堆 + 元空间 + 直接内存；只设 `-Xmx` 不够 |
| 多副本 | 单机 JVM 锁不够 → **并发 V5 Redis** |
| 滚动/重试 | 重复请求 → **并发 V7 幂等** |

K8s（只看图口述，不上集群）：

- Deployment = 期望副本与滚动策略  
- Service = 稳定虚拟 IP / DNS  
- liveness vs readiness  

### 下午后半（可选但建议当天收口）：CI

Gitee / GitHub Actions 最小流水线：

```text
push ms/dev → checkout → setup JDK17 → mvn -DskipTests package
```

- [ ] 流水线绿  
- [ ] 能讲：密钥放哪里、产物是 jar 还是镜像、为何先不自动 SSH 上传生产  

### Day 2 结束标准

- [ ] compose 一键起 gateway + order（中间件仍宿主机）  
- [ ] 口述 5 句过关  
- [ ] （可选）CI 绿  
- [ ] 路线图 P6 勾选；有余力打小版本如 `v3.7.0`（容器化里程碑）

## 5. 每日时间盒（防发散）

| 时段 | Day1 | Day2 |
|------|------|------|
| 上午 | order Dockerfile 跑通 | compose 联调 |
| 下午 | gateway + 踩坑笔记 | 口述 + CI 可选 |
| 超时就砍 | 不做 inventory/ai 镜像 | 不做自动部署、不做 K8s 实装 |

卡住超过 45 分钟：先记录现象（日志 / Nacos 实例 IP / `docker inspect` 网络），再改方案，别同时改 5 个环境变量。

## 6. 与「手动上传」的简历说法

> 学习环境用 Docker 将 gateway、order 等业务服务镜像化，本机 compose 联调；Nacos/DB 等中间件仍宿主机复用。生产门店仍手动/脚本发布，避免动现网；理解多副本与滚动发布，并与库存并发 V5（分布式锁）、V7（幂等）对照讲解。
