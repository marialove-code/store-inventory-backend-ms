## 3. 分块说明（贴近生产怎么理解）

### 3.1 已完成且「学习版 = 够讲生产故事」

这些在面试里要会说：**我们做了什么、刻意没做什么、生产会怎么补**。

| 块 | 生产叙事（各用 2～3 句） |
|----|--------------------------|
| 微服务 | 按业务拆分 + 注册发现 + 网关；家用单机部署，生产可多实例 |
| 并发 | V4 正确性底座；V5 多实例；V6 削峰；V7 幂等与补偿 |
| ES | 检索副本；PG 真相；学习全量 reindex，生产 MQ/Canal |
| RAG | 检索增强不微调；向量副本；库存仍回 PG |
| AI | Prompt + 降级；数字不靠模型瞎编 |

**不必为了「更像大厂」再补：** 多机房、全链路追踪平台、完整混沌工程、向量集群。

---

### 3.2 云原生（当前）——建议实操到哪为止

| 项 | 建议 | 原因 |
|----|------|------|
| 本机 `order`（及可选五服务）容器跑通 | **建议做完** | 你已通 order；建立「镜像/容器」手感 |
| `docker-compose` 起业务服务 | **建议做**（可选五服务） | 比五遍超长 `docker run` 真实 |
| 中间件也全进 compose（Nacos/PG/Nginx） | **不必** | 家用已稳；动库和入口风险大 |
| 服务器上全部改为容器 | **可选，非必须** | 偶尔用、脚本已能发；简历有本机容器演示够 |
| K8s 实装 | **不要** | 单机无收益；口述 Deployment/Service/探针 |
| SSH/Agent 自动上生产（仅 order） | **已按中厂脚本方案落地** | push 只 CI；tag/手动才 CD；见 CI-CD 文档 |

**生产贴近说法（有容器、无 K8s 也成立）：**

> 业务服务镜像化，本机/单机用 compose 编排；数据与 Nginx 留宿主机。多副本与滚动发布的需求，用并发 V5/V7 的设计回应；编排层用 K8s 概念口述即可。

---

### 3.3 明确「没必要实操」清单（按你的体感）

下面这些 **可以不做代码、不做环境**，只保留口述或文档：

1. **Seata 落地** —— 用「锁库存 + 补偿 / 本地消息」讲清取舍即可  
2. **K8s 集群 / minikube 实装**  
3. **全服务自动部署 / 无确认直接干生产**（order 已做「CI 自动 + CD 手动确认」即可）  
4. **ES / 向量 的 Canal、MQ 增量同步代码**  
5. **生产级监控全家桶**（Prometheus+Grafana+全链路）——有基础日志/简单监控即可  
6. **把 PostgreSQL、Nginx 强行容器化**  
7. **五服务 + 全部中间件「compose 全家桶」一把梭**  
8. **投简历前再开 Agent 框架大坑**  

可选、有空再做（低优先级）：

- Gitee/GitHub Actions：push → 编译通过  
- 服务器上只把 **order/inventory** 试跑成容器（platform 后迁）  
- 商品变更时同步一条向量/ES（小功能，非主线）

## 4. 和「真实生产」的诚实对照

| 维度 | 你们现在 | 中小厂常见生产 | 你要补的是 |
|------|----------|----------------|------------|
| 部署 | 脚本 jar 为主；容器本机演示 | jar / 容器 / 少量 K8s | **会容器即可**，不必上 K8s |
| 配置 | yml + 少量 Nacos | 配置中心 + 环境隔离 | 已有雏形，够讲 |
| 数据 | 单库 PG | 同左或读写分离 | **不必上读写分离** |
| 检索 | ES / pgvector 学习版 | 常有同步与监控 | **会讲同步与边界** |
| 高可用 | 单机 | 多副本 + 探活 | 口述 + V5/V7 挂钩 |
| 发布 | order：Gitee Go + 脚本；其它手动 | CI + 灰度 | **order 已够讲**；灰度可口述 |

结论：你的项目是 **「完整业务 + 关键技术点可演示」的学习/家用生产混合体**，不是缺一大块业务，而是 **运维形态还可选加深**。加深到「本机/单机容器 + 能讲 K8s/CI」对目标薪资带通常够。
