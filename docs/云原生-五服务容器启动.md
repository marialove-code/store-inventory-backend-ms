# 云原生 · 五个微服务容器启动（本机 Docker Desktop）

> 你已有：`es-dev`、`rabbitmq`、`order-c`。下面把 **gateway / platform / inventory / order / ai** 都打成镜像并用 compose 一起起。  
> **不要动**：本机 Nacos、PostgreSQL（隧道）、公网 Redis；ES/MQ 继续用 Desktop 里现有容器。

---

## 开始前

1. **停掉 IDEA 里正在跑的微服务**（8080～8084 别被 java 占用）  
2. Docker Desktop 里可先 Stop 旧的 `order-c`（后面 compose 会重建）  
3. 确认 Nacos、PG 隧道正常；`es-dev`、`rabbitmq` 为 Running（你截图里已有）

---

## 步骤 1：IDEA 根工程打包（五个 jar 一次出齐）

Maven 面板 → 最上面 **`store-inventory-backend-ms`** → Lifecycle → **`install`**（跳过测试）

成功后确认这些文件都在：

```text
gateway-service\target\gateway-service-3.6.0.jar
platform-service\target\platform-service-3.6.0.jar
inventory-service\target\inventory-service-3.6.0.jar
order-service\target\order-service-3.6.0.jar
ai-service\target\ai-service-3.6.0.jar
```

> 改过 `application-docker.yml` 后必须重新 install，镜像才会带上新配置。

---

## 步骤 2：IDEA Terminal 构建五张镜像

```powershell
cd E:\Projects\store-inventory-backend-ms

docker build -f gateway-service/Dockerfile -t inventory-gateway:3.6.0 .
docker build -f platform-service/Dockerfile -t inventory-platform:3.6.0 .
docker build -f inventory-service/Dockerfile -t inventory-inventory:3.6.0 .
docker build -f order-service/Dockerfile -t inventory-order:3.6.0 .
docker build -f ai-service/Dockerfile -t inventory-ai:3.6.0 .
```

看一眼：

```powershell
docker images inventory-*
```

---

## 步骤 3：准备密码文件（只做一次）

```powershell
cd E:\Projects\store-inventory-backend-ms
copy docker-compose.dev.env.example .env
notepad .env
```

改成真实的：

- `DB_PWD=...`
- `DASHSCOPE_API_KEY=...`（ai 要用；没有可先空着，ai 可能降级）
- `REDIS_HOST` 一般保持 `120.53.88.204`

---

## 步骤 4：一键启动五个业务容器

```powershell
cd E:\Projects\store-inventory-backend-ms

# 若旧 order-c 还在，先停掉
docker rm -f order-c gateway-c platform-c inventory-c ai-c 2>$null

docker compose -f docker-compose.dev.yml --env-file .env up -d
```

Docker Desktop 里应看到：`gateway-c`、`platform-c`、`inventory-c`、`order-c`、`ai-c`（加上原来的 es-dev、rabbitmq）。

看某个服务日志：

```powershell
docker logs -f order-c
docker logs -f gateway-c
```

---

## 步骤 5：探活（浏览器）

| 服务 | 地址 |
|------|------|
| order 直连 | http://localhost:8083/api/order/ping |
| inventory | http://localhost:8082/api/inventory/ping |
| platform | http://localhost:8081/api/platform/ping |
| ai | http://localhost:8084/api/ai/ping |
| **经网关** order | http://localhost:8080/api/order/ping |

网关那条通了，说明：容器注册 Nacos + 网关 `lb://` 转发都 OK。

前端仍代理 `8080` 时，可直接开前端联调（本机 IDEA 微服务要先停干净）。

---

## 常用命令

```powershell
# 停五个业务（不动 es / rabbitmq）
docker compose -f docker-compose.dev.yml down

# 只看状态
docker compose -f docker-compose.dev.yml ps
```

---

## 常见问题

| 现象 | 处理 |
|------|------|
| 端口占用 | 停 IDEA 里的 java 服务 |
| Feign / 网关 503 | 等各服务日志出现 `Started` 再试；Nacos 里应看到 `host.docker.internal` |
| ai 起不来 | 检查 `.env` 里 `DASHSCOPE_API_KEY` |
| PG 连不上 | 隧道 5432、`.env` 的 `DB_PWD` |

---

## 和「一长串 docker run」的关系

现在用 **compose + `.env`**，不用再手敲五遍超长 `-e`。  
原理没变：还是把 Nacos/DB/Redis 地址传进容器。
