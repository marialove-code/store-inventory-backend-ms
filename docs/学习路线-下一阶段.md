## P1 — 并发 V5（Redis）【下一个就做这个】

**做什么**

- 在 `order-service` 把 `OrderCreateConcurrencyV5` 从占位做成可压测实现  
- 主方案二选一（先做一种讲透）：  
  - A. 分布式锁（按 `goodsId`）+ 再调库存 lock  
  - B. Redis Lua 预扣 / 原子扣减 + 落库  
- JMeter：`version=v5`，对比 V4（正确性：不超锁；性能可记一笔）  
- 文档：`并发/01-压测数据.md` 补 V5 结果 + 新建 `并发/问答-V5.md`（约 15～20 问）

**做完标准**

- [x] 代码：`OrderCreateConcurrencyV5` + `GoodsStockRedisLock`（方案 A 分布式锁）  
- [x] 问答文档：`并发/问答-V5.md`  
- [x] `?version=v5` / `v5r` 200 并发不超锁（2026-07-19 JMeter；数据见 `并发/01-压测数据.md`）  
- [ ] 能口述：V2 为何多实例不行、V4 与 V5 各自适用  
- [ ] Key 设计、过期、续期/误删（Redisson 或自研）至少一种说清  

**不做**：上 MQ、上 Seata、改正式下单默认策略（仍走压测版本参数）。

## P2 — 并发 V6（MQ）

**做什么**

- 接口快速受理 → 发消息 → `OrderLockStockConsumer` 异步 lock + 落库  
- MQ 选型：优先 **RabbitMQ 或 RocketMQ 其一**（面试常考，装一个即可）  
- 压测关注：接口 RT 下降、最终库存正确（允许短暂延迟）  
- 文档：`并发/问答-V6.md`（最终一致、重复消费、积压）

**做完标准**

- [x] `version=v6` 能跑通；消费者失败可观察  
- [x] 能画：同步链路（V4/V5）vs 异步链路（V6）  
- [x] 200 并发压测：HTTP 秒回、最终 lockStock=100、不超锁（2026-07-20 **JMeter GUI**：平均 93ms / 258.4/s）  

**依赖**：本机/服务器有一个 MQ；库存仍走 Feign/HTTP。  

**下一阶段**：P3 并发 V7（幂等 + 补偿）。

## P3 — 并发 V7（幂等 + 补偿）

**做什么**

- 幂等键（请求头或字段）+ 唯一约束 / Redis setnx  
- 补偿任务：扫描「订单与锁库存不一致」并修复或告警（`OrderConcurrencyCompensateJob`）  
- 建议：先在 **V5 同步链** 上做幂等，再挂到 V6 消费端防重复  
- 文档：`并发/问答-V7.md`；V1～V7 总表收口进 `并发/01-压测数据.md`

**做完标准**

- [x] 同一幂等键连点只锁一次库存（Apifox + JMeter 200 同 key，`lockStock=1`）  
- [x] 能口述：至少一种不一致场景 + 补偿怎么修  
- [x] 面试一句话串完 V1～V7  

**本阶段结束后**：库存并发故事可宣称「主线讲完」（标签 `v3.5.0`）。
