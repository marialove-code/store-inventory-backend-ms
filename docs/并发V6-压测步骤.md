# 并发 V6 测试步骤（RabbitMQ 异步锁库存）

> 前置：本机 Docker 已起 RabbitMQ（5672 / 15672），Nacos + inventory(8082) + order(8083) 可跑。  
> 压测路径仍是 concurrency（`dev` profile），**不要**打正式 `/order/info/add`。

---

## 总顺序

```text
1. docker 确认 rabbitmq 容器 Up
2. 起 Nacos → inventory → order（dev）
3. 管理台确认队列 order.concurrency.lock.stock（order 启动后会自动声明）
4. stock/reset
5. 冒烟：POST ?version=v6 打 1～3 次
6. 查 stock/result + 订单表 / 日志
7.（可选）JMeter 小并发感受接口 RT
```

---

## 1. RabbitMQ

```powershell
docker ps
# 应看到 rabbitmq 端口 5672、15672
```

管理台：http://localhost:15672 （guest / guest）  
登录后看 **Queues** → `order.concurrency.lock.stock`（order-service 启动后出现）。

## 3. 和 V5 对比（口述）

| | V5 | V6 |
|--|----|----|
| 接口线程 | 同步做完锁库存 | 只发消息 |
| RT | 高（排队抢锁） | 应明显更低 |
| 一致性 | 强一致（返回即已锁） | **最终一致**（返回后才锁） |
| 库存正确性 | Redis 锁互斥 | 消费者内走 V4 原子 SQL |

---

## 4. 常见坑

| 现象 | 处理 |
|------|------|
| 发送消息失败 | `docker ps` 看 Rabbit 是否 Up；端口 5672 |
| 接口成功但库存不变 | 看 order 消费者日志是否报错；Nacos/inventory 是否通 |
| 队列不存在 | 先启动 order-service，由 `RabbitMqConfig` 声明队列 |
