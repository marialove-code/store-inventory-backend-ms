# 并发 V5 / V5r 测试步骤（先干什么、后干什么）

> 微服务压测：订单 **8083**，库存 **8082**，需 **Redis**。  
> 仅 `SPRING_PROFILES_ACTIVE=dev`（或默认 dev）才有压测接口。  
> **不要**打正式 `POST /order/info/add`，要用 concurrency 路径。

---

## 总顺序（记这个就行）

```text
1. 起依赖（Redis → inventory → order）
2. 冒烟（单次 v5 / v5r 能成功）
3. 重置库存
4. JMeter 压 v5（200 并发）
5. 看结果（stock/result）
6. 再重置
7. JMeter 压 v5r
8. 再看结果、记表
```

---

## 第一步：启动服务

本机 PowerShell 示例（密码改成你的）：

```powershell
# 确认 Redis 在跑（本机 6379）
# 确认 PostgreSQL 在跑

$env:DB_PWD="你的库密码"
$env:REDIS_HOST="127.0.0.1"
$env:REDIS_PWD="你的Redis密码"   # 无密码可留空或不设
$env:SPRING_PROFILES_ACTIVE="dev"

# 终端 1：库存
cd E:\Projects\store-inventory-backend-ms\inventory-service
mvn spring-boot:run

# 终端 2：订单（等库存起来后再起）
cd E:\Projects\store-inventory-backend-ms\order-service
mvn spring-boot:run
```

检查端口：

```text
8082 → inventory
8083 → order
6379 → Redis
```

Nacos（8848）若本地联调用到了再开；压测 concurrency **不强制** Gateway。

---

## 第二步：冒烟（先别上 200 并发）

用 Apifox / Postman / curl 各打 **1 次**：

### 2.1 重置（可选，冒烟前建议做）

```http
POST http://localhost:8083/api/order/concurrency/stock/reset
```

无 Body。默认商品小米17，`stock=100`，`lockStock=0`。

### 2.2 手写 V5 下一单

```http
POST http://localhost:8083/api/order/concurrency/order/add?version=v5
Content-Type: application/json
```

```json
{
  "userName": "smoke-v5",
  "goodsId": "2064625692771397632",
  "goodsName": "小米17",
  "costPrice": 3999,
  "salePrice": 4399,
  "buyQty": 1,
  "remark": "smoke V5"
}
```

期望：`code=200`，文案含「V5：Redis 分布式锁」。

### 2.3 Redisson V5r 下一单

同上，只改：

- URL：`?version=v5r`
- `remark`：`"smoke V5r"`

期望：文案含「V5r：Redisson」。

若这里就失败：先看 order 日志（Redis 连不上 / Redisson 起不来 / 库存服务不通）。

---

## 第三步：正式压测前重置（必做）

每次压测前都要重置，否则可用库存被吃光会全员「库存不足」。

```http
POST http://localhost:8083/api/order/concurrency/stock/reset
```

可再确认一眼：

```http
GET http://localhost:8083/api/order/concurrency/stock/result
```

期望大致：`stock=100`，`lockStock=0`，`usableStock=100`，`overLocked=false`。

---

## 第四步：JMeter 压 `v5`

### 4.1 线程组

| 项 | 值 |
|----|-----|
| 线程数 | **200** |
| Ramp-Up | **1** 秒 |
| 循环次数 | **1** |

### 4.2 HTTP 信息头

| 名称 | 值 |
|------|-----|
| Content-Type | `application/json` |

微服务压测接口 **不需要** Authorization。

### 4.3 HTTP 请求

| 项 | 值 |
|----|-----|
| 方法 | **POST** |
| 服务器 | `localhost` |
| 端口 | **8083**（不是 8080） |
| 路径 | `/api/order/concurrency/order/add?version=v5` |

Body：

```json
{
  "userName": "jmeter-t${__threadNum}",
  "goodsId": "2064625692771397632",
  "goodsName": "小米17",
  "costPrice": 3999,
  "salePrice": 4399,
  "buyQty": 1,
  "remark": "JMeter V5"
}
```

### 4.4 监听器

- 加 **汇总报告**（看平均 RT、吞吐量）  
- 「查看结果树」线程多时容易卡，调试用即可  

点运行，等全部结束。

---

## 第五步：看 `v5` 结果（以业务为准）

```http
GET http://localhost:8083/api/order/concurrency/stock/result
```

**合格标准：**

| 字段 | 期望 |
|------|------|
| stock | 100 |
| lockStock | **≤ 100**（通常 = 100） |
| usableStock | ≥ 0（通常 = 0） |
| overLocked | **false** |
| pendingOrderCount | 约 **100**（成功锁单数） |

说明：

- JMeter「异常 % = 0」**不等于** 200 单全成功（约 100 成功 + 100 业务失败很正常）。  
- 以 `overLocked=false` 和 lockStock≤100 为准。

把汇总报告的平均响应、吞吐记下来，方便和 V4/V5r 比。

---

## 第六步：再重置 → 压 `v5r`

1. 再调一次：

```http
POST http://localhost:8083/api/order/concurrency/stock/reset
```

2. JMeter **只改两处**（其它不动）：

- 路径：`...?version=v5r`
- Body `remark`：`"JMeter V5r"`

3. 再跑 200 并发。

4. 再查：

```http
GET http://localhost:8083/api/order/concurrency/stock/result
```

合格标准与第五步相同。

## 常见问题（按顺序排查）

| 现象 | 先查 |
|------|------|
| 连接拒绝 8083 | order 没起，或 profile 不是 dev |
| 全是库存不足 | 忘了 **reset** |
| 获取锁超时很多 | Redis 慢/挂了，或 `lock-wait-ms` 太小 |
| v5 通、v5r 起不来 | order 日志里 Redisson / Redis 配置 |
| 端口写成 8080 | 微服务应用 **8083** |
| 打到 Gateway 9080 | 可以，但本步骤默认直连 8083 更简单 |

---

## 一句话清单

1. Redis + inventory(8082) + order(8083, dev)  
2. 冒烟 `v5` / `v5r` 各 1 单  
3. `stock/reset`  
4. JMeter 200 → `version=v5` → `stock/result`  
5. 再 `reset` → JMeter → `version=v5r` → `stock/result`  
6. 记表，确认两次都 `overLocked=false`
