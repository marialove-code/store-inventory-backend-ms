# 业务流转图

> 本文档描述门店库存管理系统核心业务的流转逻辑，基于当前代码实现整理。

---

## 1. 用户认证流转

```mermaid
sequenceDiagram
    participant U as 用户/前端
    participant A as AuthController
    participant S as AuthServiceImpl
    participant DB as PostgreSQL
    participant R as Redis

    U->>A: POST /auth/login
    A->>S: login(dto)
    S->>DB: 查询用户 + 校验密码
    S->>DB: 查询角色 + 权限
    S->>S: 签发 AccessToken + RefreshToken
    S->>R: 存储登录态 + 权限缓存
    S->>DB: 记录登录日志
    S-->>U: 返回双 Token

    Note over U,R: 后续请求携带 Bearer Token

    U->>A: 业务接口请求
    A->>A: JwtAuthenticationFilter 校验
    A->>R: 验证 Redis 登录态
    A->>A: PermissionAspect 权限校验
    A-->>U: 返回业务数据

    U->>A: POST /auth/refreshToken
    A->>S: refreshToken()
    S->>R: 校验 RefreshToken
    S-->>U: 返回新 AccessToken
```

## 3. 商品管理流转

```mermaid
flowchart LR
    subgraph 基础数据
        A[品牌管理<br/>goods_brand] --> C[商品管理<br/>goods_product]
        B[分类管理<br/>goods_category] --> C
    end

    C --> D{上下架}
    D -->|上架 shelf_status=1| E[可售商品]
    D -->|下架 shelf_status=0| F[不可售]

    E --> G[创建库存记录<br/>inventory_stock]
    G --> H[库存实时表]
```

**商品新增联动**：

1. 新增 `goods_product` 记录
2. 同步初始化 `inventory_stock`（库存为 0，状态=缺货或正常）
3. 设置 `stock_warn` 预警阈值

## 4. 库存管理流转

### 4.1 入库流程

```mermaid
flowchart TD
    A[POST /inventory/stockin] --> B[参数校验]
    B --> C[生成入库单号 receipt_no]
    C --> D[插入 inventory_in]
    D --> E[StockService.increaseStockFlow]
    E --> F[inventory_stock.stock += qty]
    F --> G[写入 inventory_flow<br/>operate_type=1]
    G --> H[refreshStatus 刷新库存状态]
    H --> I{stock vs stock_warn}
    I -->|stock > warn| J[status=1 正常]
    I -->|0 < stock ≤ warn| K[status=2 预警]
    I -->|stock = 0| L[status=3 缺货]
```

### 4.2 出库流程

```mermaid
flowchart TD
    A[POST /inventory/stockout] --> B[参数校验 + 库存充足校验]
    B --> C[生成出库单号 outbound_no]
    C --> D[插入 inventory_out]
    D --> E[StockService.decreaseStockFlow]
    E --> F[inventory_stock.stock -= qty]
    F --> G[写入 inventory_flow<br/>operate_type=2]
    G --> H[refreshStatus 刷新库存状态]
```

### 4.3 库存操作类型

| operate_type | 场景 | 库存变动 |
|--------------|------|----------|
| 1 | 入库 | stock + qty |
| 2 | 出库 | stock - qty |
| 3 | 锁定（下单） | lock_stock + qty |
| 4 | 解锁（取消） | lock_stock - qty |
| 5 | 调整 | 手动调整 |

## 5. 订单全生命周期流转

### 5.1 订单状态机

```mermaid
stateDiagram-v2
    [*] --> 待支付: 创建订单 + 锁定库存
    待支付 --> 待发货: 确认支付
    待支付 --> 已取消: 取消订单 + 解锁库存

    待发货 --> 已发货: 确认发货 + 扣减库存
    待发货 --> 已取消: 取消订单 + 解锁库存

    已发货 --> 已收货: 确认收货
    已发货 --> 退款中: 申请退款

    已收货 --> 退款中: 申请退款

    退款中 --> 退款完成: 审核通过 + 退货入库
    退款中 --> 待发货: 审核拒绝（恢复状态）
    退款中 --> 已发货: 审核拒绝（恢复状态）
    退款中 --> 已收货: 审核拒绝（恢复状态）

    已取消 --> [*]
    已收货 --> [*]
    退款完成 --> [*]
```

### 5.2 创建订单

```mermaid
sequenceDiagram
    participant U as 用户
    participant O as OrderInfoService
    participant S as StockService
    participant DB as 数据库

    U->>O: POST /order/info
    O->>DB: 校验商品存在 + 库存充足
    O->>DB: 生成订单号，插入 order_info（status=0）
    O->>S: lockStock(goodsId, qty)
    S->>DB: lock_stock += qty
    S->>DB: 写入流水 operate_type=3
    O-->>U: 订单创建成功
```

### 5.3 支付 → 发货 → 收货

```mermaid
sequenceDiagram
    participant A as 管理员
    participant O as OrderInfoService
    participant D as OrderDeliveryService
    participant S as StockService
    participant DB as 数据库

    A->>O: PUT /order/info/{id}/pay
    O->>DB: order_status: 0→1
    O->>DB: 插入 order_delivery（待发货）

    A->>D: PUT /order/delivery/{id}
    D->>S: decreaseStockFlow(goodsId, qty)
    S->>DB: stock -= qty, 写流水
    D->>DB: delivery status→2, order status→2

    A->>O: PUT /order/info/{id}/receive
    O->>DB: order_status: 2→3
    O->>DB: delivery status→3
```

### 5.4 退款流程

```mermaid
flowchart TD
    A[POST /order/refund 申请退款] --> B{订单状态}
    B -->|已支付/已发货/已收货| C[创建 order_refund<br/>status=0 待审核]
    C --> D[保存原始订单/发货状态]
    D --> E[order_status → 4 退款中]

    E --> F{管理员审核}
    F -->|通过| G[StockService.increaseStock 退货入库]
    G --> H[order_status → 5 退款完成]
    F -->|拒绝| I[恢复 original_order_status]
    I --> J[refund_status → 2 拒绝]
```

## 10. 关键业务规则汇总

| 业务 | 规则 |
|------|------|
| 下单 | 创建订单时锁定库存，防止超卖 |
| 支付 | 仅待支付订单可支付，支付后生成发货单 |
| 发货 | 仅待发货可发货，发货时扣减真实库存 |
| 取消 | 待支付/待发货可取消，释放锁定库存 |
| 退款 | 已支付/已发货/已收货可申请，通过后退货入库 |
| 入库 | 事务保证：入库单 + 库存增加 + 流水记录 |
| 出库 | 事务保证：出库单 + 库存扣减 + 流水记录，库存不足拒绝 |
| 预警 | stock ≤ stock_warn 且 > 0 为预警，stock = 0 为缺货 |
| 注册 | 自动绑定普通用户角色（roleId=3） |
| 权限变更 | 清除 Redis 权限缓存，下次请求生效 |
