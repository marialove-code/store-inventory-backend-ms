# 系统架构设计

> 项目：智联数贸平台 · 门店库存管理后端（`store-inventory-backend`）  
> 版本：1.0.0-SNAPSHOT  
> 架构风格：单体分层架构（Spring Boot Monolith）

---

## 1. 系统概述

本系统是一套面向**门店与配件供应链**场景的进销存 + 运营管理系统后端，提供用户认证、RBAC 权限控制、商品管理、库存管理、订单管理、门店收银、系统监控等核心能力。

### 1.1 设计目标

| 目标 | 实现方式 |
|------|----------|
| 前后端分离 | RESTful API + JWT 无状态认证 |
| 细粒度权限 | RBAC 用户-角色-权限 + 按钮级控制 |
| 高可维护 | 领域模块化分包 + 统一分层 |
| 可观测 | 操作日志 + API 监控 + 服务监控 |
| 数据安全 | BCrypt 密码 + 逻辑删除 + Redis 会话管控 |

## 4. 模块架构

### 4.1 业务域划分

```
modules/
├── auth          ── 认证中心（登录态管理）
├── system        ── 系统管理（RBAC + 日志 + 在线用户）
├── goods         ── 商品域（品牌/分类/商品）
├── invertory     ── 库存域（入库/出库/预警/流水）
├── order         ── 订单域（订单/发货/退款）
├── shop          ── 门店域（收银/销售记录）
├── dashboard     ── 看板域（管理端首页）
├── monitor       ── 监控域（API/Redis/服务器）
└── own           ── 个人中心
```

### 4.2 模块依赖关系

| 模块 | 依赖 | 被依赖 |
|------|------|--------|
| auth | system(user/role/permission) | 所有需登录模块 |
| system | auth | goods, invertory, order, monitor |
| goods | system | invertory, order |
| invertory | goods | order |
| order | goods, invertory | dashboard |
| shop | — | dashboard |
| monitor | auth | — |
| dashboard | order, invertory, monitor | — |

## 5. 安全架构

### 5.1 认证架构

```
┌──────────┐    登录     ┌──────────────┐    签发     ┌──────────┐
│  前端     │ ─────────> │ AuthService   │ ─────────> │ JwtUtil  │
└──────────┘             └──────┬───────┘             └──────────┘
                                │ 存储
                                ▼
                         ┌──────────────┐
                         │    Redis      │
                         │ Token + Perm  │
                         └──────┬───────┘
                                │ 校验
                                ▼
                         ┌──────────────┐
                         │ JWT Filter   │
                         └──────────────┘
```

### 5.2 授权架构

- **第一层**：Spring Security → 是否已登录
- **第二层**：`@RequiresPerm` AOP → 是否拥有权限码
- **特权**：`SUPER_ADMIN` 角色绕过第二层

## 6. 数据架构

### 6.1 存储选型

| 存储 | 用途 | 数据特点 |
|------|------|----------|
| PostgreSQL | 业务主数据 | 持久化、事务、关系查询 |
| Redis | 会话/权限/限流 | 高速读写、TTL 过期 |
| 本地文件系统 | 图片上传 | 头像、商品图、品牌 Logo |

### 6.2 缓存策略

| 缓存项 | Key | TTL | 失效策略 |
|--------|-----|-----|----------|
| 登录态 | `user:token:{uid}:access:{token}` | 与 Token 一致 | 登出/过期/强踢 |
| 权限列表 | `user:perm:{uid}` | 与 RefreshToken 一致 | 角色/权限变更时主动清除 |
| 设备映射 | `user:device:{uid}` | 与 RefreshToken 一致 | 踢设备/登出 |
| Redis 大 Key | 定时采集缓存 | 定时任务刷新 | `RedisBigKeyCollectTask` |

## 8. 横切关注点

### 8.1 AOP 切面清单

| 切面 | 注解 | 顺序 | 职责 |
|------|------|------|------|
| RateLimitAspect | `@RateLimit` | — | 接口限流 |
| PermissionAspect | `@RequiresPerm` | @Order(3) | 权限校验 |
| OperationLogAspect | `@OperationLog` | — | 操作审计 |
| ApiMonitorAspect | — | — | API 耗时采集 |

### 8.2 全局异常处理

| 异常类型 | 处理方式 |
|----------|----------|
| BusinessException | 返回业务错误码 + message |
| PermissionException | 返回 1201 无权限 |
| MethodArgumentNotValidException | 返回 1301 参数错误 |
| Exception | 返回 10500 系统繁忙 |

## 11. 非功能性需求

| 指标 | 设计 |
|------|------|
| 可用性 | 全局异常兜底，业务异常不崩溃 |

| 可维护性 | 模块化分包，统一 Result 响应，Knife4j 自动文档 |
| 可观测性 | 登录/操作日志，API 监控，服务器监控 |
| 性能 | Redis 权限缓存，MyBatis-Plus 分页，连接池 |
| 兼容性 | JDK 17，Spring Boot 3，PostgreSQL 14+ |
